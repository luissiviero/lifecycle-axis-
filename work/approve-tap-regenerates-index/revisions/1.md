# Revision 1: heal every index only on the default branch, write the item's own two elsewhere, and judge a rename's source

## Proposal
Five changes to `spec.md`, the first two clearing the trigger's Blocking and Major findings, the rest the
nits both reviewers raised against the same lines; and the matching changes to `plan.md`.

1. **R-2 becomes ref-scoped.** On the default branch the tap writes and commits every generated index it
   changed, as signed: a grant lands only there (`approve_dispatch.py:89-96`, R-8 of `approve-by-dispatch`),
   there is no pull request whose mode a foreign index could flip, and drift on `main` is exactly what
   the owner asked the tap to heal. On any other ref the tap writes only `work/<slug>/index.md` and
   `work/index.md`, the two paths `own_artifact` already counts as the item's own, and leaves a stale
   foreign index untouched and unstaged, reporting it on stdout so the run log says the branch carries
   drift the tap did not commit. The ref comes from `GITHUB_REF_NAME` and the default branch from the
   event payload at `GITHUB_EVENT_PATH` (`repository.default_branch`, the same field the workflow's role
   gate already reads as `github.event.repository.default_branch`); both are set by Actions on every run,
   so no workflow input, flag or step changes. When either is unknown, as in a local run or the test
   fixture without explicit values, the committer takes the narrow route: it never stages a foreign path
   without knowing it is on the default branch. `commit()` gains keyword arguments `ref` and
   `default_branch` so the suite can drive both routes; `main()` and the CLI are untouched.
2. **A rename is judged at both ends.** `changed_paths` returns the source and the destination of a
   porcelain `R`/`C` entry, so a source outside the allowlist is a stray and refuses the commit as any
   other stray does. Pinned by a case that stages a rename from a committed path outside `work/` to a
   generated-index path and asserts the source is named and `HEAD` unchanged.
3. **One `git status`, one list.** `unexpected_paths` takes the reported list from the caller, so the
   guard and the staging read the same run, which is what D5 and the comment already claimed.
4. **`regenerate` writes only what it may commit, and says what it skipped.** It takes a predicate for
   the paths it may write (the generated-index predicate on the default branch, the item's own two
   elsewhere) and reports the rendered paths whose bytes differ but which it left unwritten. This is also
   what closes the nit that a directory `INDEX_RE` rejects (a leading dot) had its index written and then
   refused as a stray naming a file nobody asked for.
5. **Three stdout shapes, all proven, and one refusal that names its cause.** `regenerated <n> index
   file(s): <sorted paths>`; `indexes already up to date`; `left <n> stale index file(s) unwritten on this
   ref: <sorted paths>`. The index-only refusal keeps its `nothing staged; approve.py wrote no change`
   text and appends `(only generated indexes changed: <paths>)`, so a run log can tell it from the
   original refusal. R-8 drops "precedes the refusal", which two separately captured streams cannot
   prove, and R-2's case asserts the exact regenerated line in a fixture where the generator's order
   (`work/index.md` last) differs from sorted order, which is what pins the sort.

`plan.md` follows: the file list gains `revisions/1.md` and `revisions/index.md`; the six new cases become
ten (`test_on_another_ref_only_the_items_indexes_are_written`, `test_unknown_ref_takes_the_narrow_route`,
`test_a_rename_source_is_judged_too`, `test_a_traversing_slug_is_refused_on_a_clean_tree`, the last pinning
the up-front `allowed_paths` call the build restored in f8b0e1d, whose operand order one reviewer found
untested); step 1's red set is restated for the cases that can be red against the current head; the proof
table and risks name the ref decision and its two sources.

This is the smallest change that clears the trigger: the alternative that keeps R-2 unconditional needs
`own_artifact` in `scripts/check_artifact_chain.py` to accept `work/*/index.md`, a `locked-paths` file this
item may not touch and whose one-item-per-pull-request rule exists for a reason; a workflow input for the
ref touches a protected file and ends the delegated queue. Not proposed: refusing on a side branch when a
foreign index is stale (fails the owner's tap on a branch whose drift is not the item's), or writing the
foreign index without staging it (the stray guard would then refuse it).
