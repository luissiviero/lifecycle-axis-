## Risks
- Risk: the workflow cannot be exercised before merge (schedule and `workflow_dispatch` only) → mitigation: YAML parse check, the five `BandsWorkflow` grep cases, the `config` job's JSON produced locally by the same script, and one manual dispatch by the owner after merge; a failure there is an incident for this item, not a silent night.
- Risk: the full scan re-reports an old spike nightly → mitigation: the comment-or-create step; accepted in spec C2.
- Risk: the stdlib parser rejects a future `bands.yaml` edit → mitigation: it fails the `config` job with the line named; `test_real_file_yields_two_github_metrics` catches it in `verify.sh` before merge.
- Risk: `gh issue list --search` semantics change or the title is edited → mitigation: the filter is a `--jq` prefix match on titles from `--json`, not a search query; one duplicate issue is the worst case.
- Risk: the `sdlc-gate.yml` scope thins the CI series so the detector reports `tested: 0` for a while → accepted; the metric doc says so; the artifact shows the series length.
- What this could break: nothing that runs in production; `bands.yml` is the only consumer of `detect_bands.py` and reads `tier` only; `test_github_metrics.py`'s end-to-end cases are tightened, not loosened.
- Options considered and not taken: a naive trailing baseline ending at `i - 1` (misses a sustained shift, spec D1); testing only the last point (misses a skipped night, D2); a `drift` tier in `bands.yaml` (workflow `if:` lines would need it, D3); PyYAML in the workflow (D4); `Bash(git log *)` in the 2σ tools (D5); a wall-clock `--days` cutoff for pulls (D6).
