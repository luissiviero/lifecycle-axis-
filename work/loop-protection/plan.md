## Risks
- Risk: `fm_value` is created by the `control-plane-visibility` item and only consumed here; if that item's shape drifts (name, casefolding, the `any` argument), steps 2-3 fail → mitigation: step 1 checks for it; the deviations log records any rename; the R-4 cases pin the behaviour this item needs.
- Risk: the `permissions.deny` list refuses `WebFetch`/`curl` in every session here → mitigation: the owner is told in the PR body; the settings file is now protected, so the change back is a labelled PR.
- Risk: a hook edit that breaks `protect-tests.sh` locks this session's Edit tool → mitigation: `bash -n` and `scripts/hooktest.py` from a second shell before the next tool call.
- What this could break: an adopter whose `scripts/checks/*.sh` lost its mode on a Windows checkout gets `VERIFY: FAIL` instead of a silent pass; the message names the file and the env override.
- Options considered and not taken: adding `scripts` to `PROTECTED_PATHS` (D1); a `git ls-files` test instead of `-e` (D2); running verify from the base branch in CI (Q1, deferred); `Bash(git *)` in `allow` (D4).
