# Revision 1: R-2 is judged on the base ref, the pointer is validated at the boundary, and every printed line is a signed shape

## Proposal
The smallest change to `spec.md` that makes the signed text describe the code the two Important
fixes require, and nothing more:

1. **R-2 row.** The check fails when `.sdlc/active` names an item *already retired on the base ref*
   (`work/<active>/intent.md` is `superseded` on `--base`). The pull request that retires an item is
   the act in progress and gets a note; a self-check (`--base HEAD`, what `scripts/verify.sh` runs)
   has no base and gets a note. Oracles: `test_retired_active_item_is_one_clear_failure` (retired on
   `main`, checked from a later branch commit with `--base main`),
   `test_retiring_pull_request_is_a_note_not_a_failure`, `test_self_check_on_a_retired_pointer_is_a_note`.
2. **New row R-7.** `--slug` and `.sdlc/active` are validated against `SLUG_RE` before either names
   a path or a git argument; a value outside it is one `FAIL:` line with the value repr'd and
   `CHAIN: FAIL` last. `SLUG_RE` is the shape `approve_dispatch.py` and `delegated_merge.py` guard
   with, plus a leading `_` for `adopt.sh`'s `_example`, and `\Z` rather than `$` so a trailing
   newline is refused. Oracles: `test_malformed_active_pointer_is_one_clear_failure` (both sources,
   eleven subcases), `test_leading_underscore_slug_is_accepted`.
3. **Interfaces ("exact shapes").** The R-4 line gains `(git diff failed: <last stderr line>)`; the
   list gains the retiring-pull-request note, the self-check note, the malformed-value failure and
   the missing-item note, verbatim from the code.
4. **Failure modes.** "Locally, `VERIFY_CMDS` already passes `--base HEAD`, so `scripts/verify.sh` is
   unaffected" is kept for R-4 only; for R-2 the self-check is a note and the failure is CI's.
5. **Security standards §3.** "validated at the boundary with `SLUG_RE` (R-7), one character wider
   than the siblings' (a leading `_`) and named as such" replaces "is not widened".

The plan's step 3 and step 6 changes are file-list and order deviations, logged as entry 2 of the
plan's deviations log and its ledger line (2 of `max-deviations: 5`); the plan is not revised.
