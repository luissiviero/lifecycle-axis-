- Risk: `|| exit 1` appended to the wrong physical line of a continued command → mitigation: the checker parses continuations the same way and `run_evals.sh --kind hook` must stay `0 fail`; both run in `verify.sh`.
- Risk: `-G` misses an approval whose line was added with different spacing (`status:  approved`) → accepted: `approve.py` and the web editor write `status: approved`; the guard on the parsed current status still runs and the "not committed yet" note covers a miss rather than a wrong attribution.
- Risk: the trust step's `~/.claude.json` key name changes in a later Claude Code version → mitigation: pinned CLI version in the workflow (`2.1.258`); the log line that names the key is quoted in the workflow comment.
- What this could break: the PR-time eval job is unchanged; local `run_evals.sh` without a key is unchanged; the fifteen cases assert the same facts; the chain check's attribution changes only for a file whose later commits mention the phrase in prose.
- Options considered and not taken: rewriting negations as `if … then exit 1` (D1); failing skipped prompt cases by default (D2); fixtures inside `check` (D3); keeping `-S` with a narrower pathspec (D4); trusting the checkout in every job (D5); a key literal in the planted-key case (D6).

## Deviations log (append during implementation; same commit as the deviation)
- Step 3: the first fix pass touched 13 files and 20 lines, not 15 and 23. Two cases build a heredoc-shaped command inside a quoted `printf` argument for the hook to judge, and both the fix script and `check_eval_cases.py` read that `<<"EOF"` as a real heredoc, skipping the rest of the block. The checker now ignores a `<<` inside quotes (`heredoc_tag`), a test pins it (`test_heredoc_operator_inside_quotes_is_not_a_heredoc`), and the second pass reached 15 files and 23 lines as the spec lists. `test_check_eval_cases.py` therefore has eight cases, not five.
- Step 3, finding: with its negation effective for the first time, `hook-requires-plan-for-bash-write` failed. It asserted that `require-plan.sh` blocks a Bash write to `src/a.ts`, but this repo's `PLAN_REQUIRED_PATHS` is `scripts`, so the hook correctly allowed it; the assertion had been wrong since it was written and the inert `!` hid it. The case now derives the path from the first entry of `PLAN_REQUIRED_PATHS` in `.sdlc/config.env`, so it holds in the kit (`scripts/`) and in an adopted repo (`src/`). This is the one fixed case whose text changed beyond `|| exit 1`; the spec's "no other text changes" did not survive the evidence.
- Proof: the suite grows by seventeen over `main` (three runner cases, four workflow cases, eight checker cases, two attribution cases), not fourteen: the checker's test module has eight cases (see the first deviation) and the plan's count did not include the two attribution cases it lists elsewhere.
- Review (PR #34): `skill-incident-names-an-eval`'s cleanup ran `git checkout -- docs/sdlc/lessons.md` unconditionally, which would discard a developer's uncommitted edit to that file when the suite runs locally. The case now snapshots the file in `setup:` and the check restores that snapshot only when the prompt changed it, so what was there before the prompt comes back, edits included. The reviewer's suggested guard (`git diff --quiet && git checkout`) would have restored only when nothing had changed; not taken.
- Step 2: the skip decision (`--require-claude` or skipped) is taken before `setup:` runs, so a prompt case that cannot run leaves no fixture behind; the spec's ordering ran setup first. Same behaviour for every case that can run.
