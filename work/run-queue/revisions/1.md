# Revision 1: the ledger actor is the bot that actually commits

## Proposal
The smallest change to `spec.md` that makes the signed text true of the code, and nothing more:

1. **R-3's two literal ledger lines** change `claude[bot]` to `github-actions[bot]`, and the
   **Interfaces** section's ledger shapes change with them. The code is right and the spec is wrong:
   the advance is performed by the delegated-merge workflow under the repository token, and no Claude
   session runs it. A ledger line reading `claude[bot]` would name an actor that did not act, and
   would contradict the commit author that the same line exists to corroborate — which is exactly
   R-3's own property, "retraceable from the ledgers alone".
2. **The failure-modes paragraph** on racing advances says what the security pass established: the
   protection is the push, which is not forced, so any commit that reached the remote first rejects
   it; the pointer re-read is a precondition for a direct call to `advance()`, not concurrency
   control. `scripts/delegated_merge.py`'s docstring and `plan.md`'s risk say the same.
3. **The oracle changes with the requirement.** `test_ledger_lines_parse_and_name_both_items` asserts
   the literal `"github-actions[bot]"` instead of `dm.ADVANCE_IDENTITY[0]`, so renaming the constant
   can no longer silently satisfy a stale spec. That is the point of the fix, not a tidy-up.

Not proposed: changing the code to write `claude[bot]`. It would make the ledger less true, and both
reviewers rejected that direction.

## Reviewer: security-reviewer (sonnet)
All four fixes hold, verified against the working tree (`python3 -m unittest scripts.test_delegated_merge`
→ 123 tests, OK; `Advance` alone → 12, OK). Nit 1: the docstring at `scripts/delegated_merge.py:927-936`
now states plainly that the non-forced push is the real protection and the pointer check only matters on
a direct call; I re-traced `run()`'s path to confirm that is still true. Nit 2: the clean-tree
precondition (`:946-947`) runs before the pointer read and refuses on any dirt anywhere, not just staged
extras — `test_a_dirty_tree_writes_nothing` exercises an *unstaged* append the old code would have missed.
Nit 3: `except (OSError, ValueError, MergeError)` (`:879`) catches `UnicodeDecodeError`. Nit 4:
`_ledger_safe()` (`:900-912`, applied at `:978-979`) replaces `|`, CR and LF; the new case confirms
`log_ledger.parse` reports zero malformed lines. The actor correction is right and in the direction
proposed: `ADVANCE_IDENTITY[0]` is the pinned commit author, `.github/workflows/delegated-merge.yml:13`
already documents "Who merges: github-actions[bot], with the repository token", and both bot strings are
equally excluded from ever reading as a valid human approver, so the swap is a pure accuracy fix with no
new authorization risk. The test change must land in the same commit as the spec edit.
verdict: revise
