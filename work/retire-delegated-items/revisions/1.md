# Revision 1: `approved-by` on a retired artifact is skipped only where the ledger shows a signature

## Proposal
The smallest change to `spec.md` that clears the trigger and keeps the intent's observables:

1. **R-1 row.** From "the chain check no longer validates `approved-by` against `.sdlc/approvers.yaml`"
   to: on a `superseded` artifact the ledger shows signed under a grant (a `-> delegated` line for it
   whose actor is the handle in `approved-by`, the line `sign.py` writes) the check does not validate
   `approved-by`; on one a human approved (no such line) the approver check stays as it is. Everything
   else in the row (the retirer read from the `-> superseded` line, the author or trailer of the
   retiring commit, the acceptance test) is unchanged. The actor binding is the security pass's
   finding on the first form of this proposal, which accepted any `-> delegated` line or a retiring
   line from `delegated`: a stray line by another handle must switch nothing off.
2. **D1.** One sentence added: the approver list is still asked about `approved-by` when the ledger
   shows no signature for the artifact, because a human-approved artifact's approver was a valid handle
   and a bot handle there is a malformed record, which the pre-existing case pins.

Why this is the smallest change: the intent's three observables all still hold (the agent-signed tree
passes, the agent-actored retiring line fails naming the line, nothing an agent can do widens); the
signature is read from the ledger the retirer and the check already read, not from `approved-by`; and
the narrowing is strictly stricter than the approved wording, so no case that passed under the approved
R-1 fails under this one except the one the trigger names, which must fail. The alternative, editing the
pre-existing case, breaks the intent's Must directly.

What else goes stale: nothing in the plan's file list or order; the R-2 acceptance test is unchanged
because the signature is read from the whole ledger, so an agent-actored retiring line on a signed
artifact is still one ledger fault. The spec's gotchas missed this case although the spec read it while
it was written (plan deviation 3 says so).

On a supervised item there is no `sign.py --revision`: the record is committed, the two reviewer sections
below are the consensus, and the owner's acceptance is a ledger line in their own hand, asked for on the
pull request.
